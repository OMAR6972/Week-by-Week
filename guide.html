1. How the whole thing works

Think of two pieces:

  • The website (what people see) — your pages, hosted free on GitHub Pages.
  • The database (the always-on filing cabinet) — run free by Supabase, 24/7, so you never keep a laptop on.

The old way: edit a file, download it, re-upload it, every single time. The new way:

You log into the admin dashboard → edit → press Save to site → it saves into the database → students see it on their next refresh. No files, no uploads, from any device including your phone.

"Frontend" = the visible website. "Backend" = the behind-the-scenes database. They talk to each other automatically.

3. Putting it online & opening on your phone

Opening a file by double-clicking shows file://… — that only works on that one computer. Your phone can't see it. To use it anywhere it must be hosted:

  1. Upload the whole site folder to your GitHub repo (replace the old files, keep the same names).
  2. GitHub → your repo → Settings → Pages shows your live link.
  3. Open that link (add /admin.html for the dashboard) on your phone → log in → edit.

The database works the same from phone or laptop, because the data lives on the internet, not your machine.

4. Editing the site (daily use) VISUAL

  1. Open your admin link, log in.
  2. Edit anything — subjects, weeks, links, staff, announcements.
  3. Press 💾 Save to site → you'll see ✓ Saved.
  4. Open the student site and refresh — your change is live.

Other buttons: ⬇ Backup downloads a spare copy of all data (see §8). ⎋ Log out signs you out. You stay logged in across refreshes otherwise.

5. Managing admins

You are the owner — the only one who can add or remove admins. Other admins can edit the site but cannot change who's an admin.

Add an admin VISUAL

  1. The new person opens the admin link and clicks Create an account (email + password).
  2. You log in, click 👥 Admins (top bar, owner only), type their email, press Add.
  3. They can now log in and edit.
If you see "No account with that email yet," it means they haven't created their account on the login screen yet. That step comes first.

Remove an admin VISUAL

Open 👥 Admins → press Remove next to their email. (The owner can't be removed.)

The SQL way SQL

In Supabase → SQL Editor:

-- see all admins
select email, is_super, added_at from public.admins order by is_super desc;

-- add an admin (they must already have an account)
insert into public.admins (user_id, email)
select id, email from auth.users where email = 'their@email.com';

-- remove an admin
delete from public.admins where email = 'their@email.com';

You can also do this with no typing in Table Editor → admins (add/delete rows by hand).

6. Changing a password

Each account has its own password — nobody shares one.

Visual VISUAL: Supabase → Authentication → Users → click the user → Reset / send recovery → follow the email link to set a new password.
Right now your login password happens to be the same text as your database password. They're different things — consider changing your login password to something else.

7. Viewing & editing raw data

Normally you edit through the dashboard. But if you ever need the raw data:

Visual VISUAL: Supabase → Table Editor → site_data. Ten rows, one per data set. Click a value cell to see/edit the JSON.
SQL SQL: select * from public.site_data;

8. Backups & the fallback file

Your site keeps an old data file, course_data.js, as a spare copy. If the internet hiccups, the page shows this spare instantly instead of going blank, then quietly swaps in the live data when it arrives. It can't break the site.

It's a frozen snapshot — it does not auto-update. To refresh the spare: press ⬇ Backup in the dashboard to download a fresh course_data.js, then upload that to GitHub. Optional; only if you want the spare current.

10. Troubleshooting

  • Change didn't show? Hard-refresh: Ctrl/Cmd + Shift + R.
  • Is live data loading? On the student site press F12 → Console → look for a green ✅ "Live data" line.
  • Can't log in? The password is your login password (not the database one). Reset it in Supabase → Authentication → Users.
  • Dashboard says "not an admin"? That account isn't in the admins list yet — add it via §5.

12. SQL cheat-sheet

You rarely need these — the dashboard covers daily life. Kept here for reference.

-- view all data sets and their sizes
select key, jsonb_typeof(value) as type from public.site_data order by key;

-- list admins
select email, is_super, added_at from public.admins order by is_super desc;

-- add / remove an admin
insert into public.admins (user_id, email)
  select id, email from auth.users where email = 'their@email.com';
delete from public.admins where email = 'their@email.com';

-- reset a single announcement area to empty (example)
update public.site_data set value = '[]'::jsonb where key = 'NEWS_DATA';
